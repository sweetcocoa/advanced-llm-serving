FlashAttention은 어디서 메모리를 아끼는가

일반적인 기준 구현은 점수 행렬을 만든 뒤 softmax와 V 곱을 실행한다. FlashAttention은 Q와 KV를 타일로 나누고, softmax의 행별 최댓값과 정규화 합, 가중 출력 누산값을 갱신합니다. 다음 타일에서 더 큰 점수가 나오면 이전 누산값을 새 최댓값에 맞춰 재조정합니다. 전체 점수 행렬을 HBM에 써 두지 않고도 같은 dense softmax 결과를 수치 오차 범위에서 얻습니다. dense prefill의 쿼리–키 쌍 수는 여전히 길이의 제곱에 비례합니다. [S1][S1] FlashAttention핵심 근거Dao et al.타일링과 HBM 이동, 정확한 dense attention

  • FA2는 thread block과 warp 사이의 작업 분할을 개선한다. [S2][S2] FlashAttention 2핵심 근거Daothread block과 warp의 작업 분할
  • FA3는 Hopper의 비동기 실행을 활용해 연산을 겹치고 저정밀도 경로를 다룬다. [S3][S3] FlashAttention 3핵심 근거Shah et al.Hopper의 비동기 실행과 저정밀 경로
  • FA4는 Blackwell에서 행렬 곱과 softmax의 처리량 차이를 고려해 파이프라인을 다시 설계한다. [S4][S4] FlashAttention 4핵심 근거Zadouri et al.Blackwell의 계산과 메모리 파이프라인

실습 1. 동일한 Q, K, V로 결과 맞춰 보기

CUDA와 PyTorch SDPA Flash backend를 사용할 수 있는 환경에서 아래 코드를 실행한다. 짧은 causal self-attention을 FP32 math 결과와 비교하는 smoke test다. 허용 오차는 이 입력과 dtype을 위한 예시이며, 배포 모델의 정확도 기준은 별도로 정한다. 순수 GPU 커널 시간 비교에는 워밍업과 CUDA event를 사용한다. [S6][S6] scaled dot product attention핵심 근거PyTorchSDPA dispatch, 강제 백엔드 선택, causal 마스크

import torch
from torch.nn.attention import SDPBackend, sdpa_kernel
from torch.nn.functional import scaled_dot_product_attention

torch.manual_seed(7)
q, k, v = [
    torch.randn(2, 8, 256, 64, device="cuda", dtype=torch.float16)
    for _ in range(3)
]

with sdpa_kernel(SDPBackend.MATH):
    expected = scaled_dot_product_attention(
        q.float(), k.float(), v.float(), is_causal=True, dropout_p=0.0
    )
with sdpa_kernel(SDPBackend.FLASH_ATTENTION):
    actual = scaled_dot_product_attention(
        q, k, v, is_causal=True, dropout_p=0.0
    )
torch.testing.assert_close(actual.float(), expected, atol=2e-3, rtol=2e-2)

강제 선택이 실패하면 PyTorch가 보고하는 지원 조건을 확인한다. 이 코드는 정사각 causal 마스크를 쓰는 prefill 예시다. KV cache가 붙는 decode 검증에서는 실제 토큰 위치에 맞는 참조 범위를 별도로 확인한다. [S6][S6] scaled dot product attention핵심 근거PyTorchSDPA dispatch, 강제 백엔드 선택, causal 마스크

실습 2. 같은 체크포인트로 서빙 백엔드 비교하기

같은 GQA 체크포인트를 두 백엔드가 모두 지원하는 장비에서 비교한다. 설치한 vLLM 버전의 지원표를 기준으로 백엔드를 지정하고 실제 선택을 시작 로그에서 확인한다. 모델, dtype, KV dtype, page size, 출력 길이, 동시 요청 수를 고정한다. [S8][S8] Attention Backend Feature Support핵심 근거vLLM백엔드 선택, 기능·장치·레이아웃 호환성

  • 긴 prefill: 같은 길이 분포에서 워밍업 후 TTFT와 피크 메모리를 기록한다.
  • 다중 요청 decode: 같은 동시성에서 TPOT, 출력 토큰 처리량과 피크 메모리를 기록한다.
  • 정확도 확인: 고정된 입력에서 가능하면 logits나 logprobs를 허용 오차로 비교한다. 장문 생성이 달라지면 첫 차이가 나온 단계의 마스크와 출력 분포를 확인한다.

GQA 장에서 구한 논리적 KV 용량은 이 실습의 기준선이다. PagedAttention 장은 물리적 페이지 배치를, Long-Context Serving 장은 sparse indexer의 비용을 추적한다.
