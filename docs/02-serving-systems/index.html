서빙 시스템 설계

이 트랙은 학습이 끝난 모델을 실제 요청 경로에서 빠르고 안정적으로 실행하는 방법을 다룬다. cache, batching, scheduling, parallelism, GPU/NPU, runtime, compiler와 운영 관측을 하나의 serving system으로 연결한다.

이 트랙을 마치면 설명할 수 있어야 하는 것

  • 모델별 inference workload를 compute, memory, mutable state 관점으로 분해할 수 있다.
  • cache와 scheduler가 latency, throughput, goodput을 어떻게 바꾸는지 설명할 수 있다.
  • GPU와 NPU를 operator support, memory hierarchy, lowering contract로 비교할 수 있다.
  • runtime과 compiler, observability를 포함한 production serving 경로를 설계할 수 있다.

섹션 순서

  • Inference Foundations
  • Cache, Batching, and Generation
  • Distributed Serving
  • Optimization and Accelerators
  • Runtime and Compiler
  • Production Operations

NPU의 위치

NPU는 별도 모델 계보가 아니다. 모델 graph를 어떤 정밀도와 operator 경계로 lowering하고 어느 runtime에 배치할지 결정하는 serving accelerator이므로 이 트랙 안에 둔다.

Sections

서빙 시스템 설계 안의 세부 영역

01

Inference Foundations

모델이 정의한 계산을 serving workload로 번역한다. Transformer inference를 prefill/decode, compute/memory, TTFT/TPOT으로 분해하고 전체 serving stack의 책임 경계를 세운다.

5 chapters
02

Cache, Batching, and Generation

단일 요청의 생성 loop와 여러 요청의 동시 실행을 연결한다. AR의 KV cache뿐 아니라 diffusion의 mutable sequence state와 recurrent depth의 variable loop depth까지 같은 runtime 질문으로 비교한다.

7 chapters
03

Distributed Serving

한 장치의 kernel 최적화를 넘어 request phase, model shard, expert와 KV state를 여러 장치와 노드에 배치하는 방법을 다룬다.

5 chapters
04

Optimization and Accelerators

정밀도, memory movement, operator fusion과 accelerator 실행 모델을 연결한다. GPU와 NPU를 성능표가 아니라 어떤 graph를 어떤 제약 아래 실행하는지로 비교한다.

4 chapters
05

Runtime and Compiler

모델 graph가 ONNX와 중간 표현을 거쳐 backend artifact로 내려가고 execution provider와 제품 runtime에서 실행되는 경로를 다룬다.

9 chapters
06

Production Operations

benchmark 결과를 실제 운영 판단으로 바꾸는 방법을 다룬다. trace, profiler, SLO와 vendor specific 도구를 이용해 병목을 재현하고 배포 선택을 검증한다.

3 chapters
