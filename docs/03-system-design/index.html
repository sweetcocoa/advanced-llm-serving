종합 시스템 설계

모델 이론과 서빙 이론을 실제 제품 선택으로 다시 결합한다. 특정 모델이나 accelerator를 홍보하지 않고 품질, latency, cost, privacy, 운영 성숙도를 같은 의사결정표에 놓는다.

이 트랙을 마치면 설명할 수 있어야 하는 것

  • cloud와 edge 배치의 품질·비용·privacy tradeoff를 설명할 수 있다.
  • workload에 맞는 model, cache, scheduler, accelerator와 runtime을 선택할 수 있다.
  • 최신 논문의 저자 보고 성능과 production readiness를 구분할 수 있다.
  • 서로 다른 생성 계보를 같은 quality-constrained goodput 기준으로 평가할 수 있다.
