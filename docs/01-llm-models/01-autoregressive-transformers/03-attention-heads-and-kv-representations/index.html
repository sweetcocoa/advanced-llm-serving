Query head와 KV head를 따로 세기

교수자: query head가 32개이고 KV head가 8개면, 연속된 query head 네 개씩 같은 K/V head를 읽는 구성을 생각할 수 있습니다. 예를 들어 첫 네 head는 KV head 0을 읽습니다. 각 query head의 Q는 여전히 다르므로 어텐션 점수와 출력도 달라질 수 있습니다. [S3][S3] GQA보조 근거Ainslie et al.그룹별 K/V 공유와 MHA·MQA 비교

BF16 요소가 2바이트이고 K와 V의 head dimension이 같다는 예다. 패딩, 페이지 여유분, 런타임의 head 복제는 빼고 논리적 크기만 센다. 학습자: 16 KiB가 4 KiB면 decode도 네 배 빨라지나요?

교수자: 줄어든 것은 논리적 KV 용량입니다. 커널이 공유 KV를 실제로 재사용하는지, KV 읽기가 전체 지연에서 얼마나 큰지까지 봐야 합니다. query head 수를 그대로 뒀다면 독립적으로 계산할 query 쪽 출력도 그대로 남습니다. [S2][S2] Fast Transformer Decoding핵심 근거ShazeerMQA의 K/V 공유와 decode 메모리 대역폭[S3][S3] GQA보조 근거Ainslie et al.그룹별 K/V 공유와 MHA·MQA 비교

MLA는 무엇을 캐시하는가

DeepSeek-V2의 MLA는 각 토큰에서 공동 KV 잠재 벡터와 위치 정보를 담는 decoupled RoPE key를 계산한다. 이후 쿼리가 읽을 K/V 정보를 이 표현으로 보존한다. 구현은 업프로젝션을 인접한 연산에 흡수해 토큰마다 모든 head의 K/V를 물리적으로 재구성하는 비용을 피할 수 있다. KV cache를 비교할 때는 KV head 개수 대신 잠재 벡터와 위치 key의 차원을 각각 확인한다. [S4][S4] DeepSeek V2 §2.1핵심 근거DeepSeek AIMLA 공동 KV 압축, decoupled RoPE, projection 흡수
